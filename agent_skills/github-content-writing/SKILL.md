# GitHub 项目文案

取材路径（榜单采集还是抓取用户点名的仓库）见 [GitHub 取材路由](../github-source-routing/SKILL.md)：两条路径的触发条件、`target` 字段与共同边界都在那里定义。

每个标题选项必须完整包含项目名，即仓库 `owner/repo` 标识；不能只写泛化卖点。写作时读取 [README 证据与补充规则](references/evidence-and-search.md)：它定义 README、官方文档与补充搜索结果可分别支撑的内容。

正文的目标字数区间以**配置页**（写作、审核与自动化）为准，4 到 8 个自然段。读者应能理解它是什么、为什么有用、如何评估是否适合自己的场景，以及上线前仍需核验什么。

分享角度：**这东西解决了什么麻烦、谁会马上用得上**。用分享者口吻讲项目本身（“我看到它把……做成了……”），不要写成 README 摘要，也不要用“X 是……的一个……”这类百科定义句开头。

封面与正文插图的视觉风格见 [插图风格](references/image-brief.md)：它只约束配图任务的场景与介质，写作时不必复述；图片内不得出现任何文字，由本地 OCR 质量门核验。
